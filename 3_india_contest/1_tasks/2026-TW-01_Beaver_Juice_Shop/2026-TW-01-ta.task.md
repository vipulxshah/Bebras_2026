பீவர் ஒரு நேரத்தில் ஒரு கலப்பானை மட்டுமே பயன்படுத்த முடியும். மேலும், ஒரு பழச்சாற்றின் சுவை மற்றொரு பழச்சாற்றின் சுவையுடன் கலந்துவிடாமல் பார்த்துக்கொள்ள விரும்புகிறார்.



நாளின் தொடக்கத்தில், மூன்று கலப்பான்களும் சுத்தமாக இருக்கும். அதன் பிறகு, பீவர் கீழ்க்கண்ட விதிகளைப் பின்பற்றி வாடிக்கையாளர்களின் பழச்சாறு கோரிக்கைகளை நிறைவேற்றுகிறார்:



* ஏற்கனவே பயன்படுத்தப்பட்ட ஒரு கலப்பானில், தற்போது கோரப்பட்ட பழச்சாற்றின் அதே சுவை இருந்தால், அந்தக் கலப்பானைப் பயன்படுத்துவார்.
* இல்லையெனில், சுத்தமான கலப்பான் இருந்தால், அதைப் பயன்படுத்துவார்.
* அதே சுவைக்கான கலப்பானும் சுத்தமான கலப்பானும் இல்லை என்றால், நீண்ட நேரமாகப் பயன்படுத்தப்படாமல் இருக்கும் கலப்பானைச் சுத்தம் செய்து, அதைப் பயன்படுத்துவார்.

## This is Informatics

In computer systems, caches are small, fast storage spaces used to speed up program execution. They are faster than main memory (RAM) but have limited capacity. Caches store recently used or frequently accessed data so that future access is faster, reducing the need to repeatedly retrieve data from slower memory and improving overall performance. When a cache is full and new data must be stored, the system must decide which existing data to remove. This decision process is called a cache replacement policy. One commonly used policy is Least Recently Used (LRU). Under LRU, the data that has not been accessed for the longest time is replaced. This policy is based on the idea that data unused for a long period is less likely to be needed again soon.

This task is a contextual simulation of the LRU concept. The three blenders represent three cache slots, and each blender's last-made flavor represents the data currently stored in the cache. When a request matches a blender's flavor, this corresponds to a cache hit. When none matches, a cache miss occurs, and a blender must be selected, cleaned, and updated according to the LRU rule. The rules to select the blender to be cleaned is a direct application of the LRU replacement strategy.

Similar mechanisms appear in daily life. For example, when working at a desk with limited space, people usually remove books that have not been used for a long time to make room for the materials currently needed. Likewise, the “recent files” list on a computer or cloud drive keeps recently opened files at the front and removes those not opened for a long time. This reflects the same principle: keep recently used items and replace those least recently used.

## This is Computational Thinking

This task emphasizes abstraction, an essential aspect of computational thinking. Although the problem is framed as a juice shop story, solving it requires ignoring irrelevant details and focusing only on information related to the blender usage and cleaning rules. Each blender is treated as a state that can be recorded and updated. The key concerns are tracking each blender’s most recent flavor and its most recent time of use. Cleaning a blender can be viewed as a state update: replacing the stored flavor with the new request's flavor. Through abstraction, the everyday scenario becomes a state management model under limited resources, which mirrors cache management in computer science.

The task also illustrates algorithmic thinking. Requests are processed one by one, and the same set of steps is repeated for each request, reflecting repetition structures in algorithms. At each step, conditional decisions are made: use a matching blender if one exists; otherwise, select and clean the blender that has not been used for the longest time. This corresponds to if–else structures. After each action, the blender’s state and usage time must be updated, and the cleaning count must be recorded when applicable. These operations demonstrate variable updates and state changes in algorithms. By combining repetition, conditionals, and state updates, students can correctly simulate the process and determine the final answer.
